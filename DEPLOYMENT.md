# Deployment Guide — GitHub Pages

This repository is configured to publish the public **Autonomous AI Researcher** website with GitHub Pages.

The GitHub Pages deployment is intentionally static:

- `index.html` serves the prompt interface.
- `assets/css/styles.css` and `assets/js/*.js` power the page.
- `_site/` is generated by `npm run build` and uploaded by GitHub Actions.
- `.github/workflows/pages.yml` deploys the generated `_site/` artifact.

The repository root also includes a `vercel.json` for optional static-site deployments on Vercel:

```json
{
  "buildCommand": "npm run build",
  "outputDirectory": "_site"
}
```

Keep this separate from the `vercel-chat-api/` backend project. Deploy the static site from the repository root only when you want Vercel to host the frontend. Deploy the API from `vercel-chat-api/`.

The root `.vercelignore` excludes the Python app, tests, run artifacts, and `vercel-chat-api/` from root frontend deployments. Without this, Vercel detects the root `api/` Python folder and tries to build serverless Python functions instead of just serving `_site`.

## Important API Limitation

GitHub Pages cannot run server code, serverless functions, or securely store provider API keys.

That means the public page can be hosted on GitHub Pages, but the prompt form needs a separately hosted HTTPS API endpoint before it can return live AI responses.

To enable live responses:

1. Deploy a small backend endpoint elsewhere. This repo includes the deployed Vercel backend project in `vercel-chat-api/`.
2. Ensure it accepts `POST` requests with this JSON body:

```json
{ "prompt": "Research question here" }
```

3. Ensure it returns this JSON shape:

```json
{
  "output": "Rendered answer text",
  "model": "gpt-4o-mini"
}
```

4. Set the endpoint URL in `assets/js/config.js`:

```js
window.AIR_SITE_CONFIG = {
    chatEndpoint: "https://autonomous-ai-researcher-chat-api.vercel.app/api/chat",
};
```

Never put `OPENAI_API_KEY`, `OPENROUTER_API_KEY`, or any other provider secret in `index.html`, `assets/js/config.js`, or any other browser file.

## Live Chat Backend

The lightweight Vercel backend is deployed at:

```text
https://autonomous-ai-researcher-chat-api.vercel.app/api/chat
```

Required Vercel production environment variables:

- `LLM_PROVIDER=openrouter`
- `OPENROUTER_API_KEY`
- `OPENROUTER_MODEL=openai/gpt-4o-mini`
- `SITE_RATE_LIMIT_PER_MINUTE`
- `PUBLIC_SITE_ORIGIN=https://research.autonomous-ai.io,https://zhaobangz.github.io`

For an OpenAI-backed backend instead, use `LLM_PROVIDER=openai`, `OPENAI_API_KEY`, and `OPENAI_MODEL=gpt-4o-mini`.

`PUBLIC_SITE_ORIGIN` must contain origins only. Do not include paths such as `/Autonomous-AI-Researcher`, because browsers send only the scheme, host, and port in the `Origin` header.

Verify the deployed backend from this machine:

```bash
npm run test:live-chat
```

## GitHub Pages Setup

In the GitHub repository:

1. Go to **Settings -> Pages**.
2. Under **Build and deployment**, set **Source** to **GitHub Actions**.
3. Push to the `main` branch.
4. Open the **Actions** tab and wait for **Deploy GitHub Pages** to complete.

The workflow publishes the generated `_site/` directory, not the full repository. This prevents Python source files, tests, run artifacts, and local configuration from being served as website files.

## Custom Domain

The repository currently includes this `CNAME`:

```text
research.autonomous-ai.io
```

Because `scripts/build-pages.js` copies `CNAME` into `_site/`, GitHub Pages will use that custom domain.

The `CNAME` file only tells GitHub Pages what domain to expect. You must also configure DNS at the domain provider:

```text
research CNAME zhaobangz.github.io
```

After DNS propagates, this command should resolve:

```bash
dig research.autonomous-ai.io
```

If you do not want the custom domain, delete `CNAME` before deploying. The default project URL will be:

```text
https://zhaobangz.github.io/Autonomous-AI-Researcher/
```

## Local Preview

Build the static Pages artifact:

```bash
npm run build
```

Preview the generated site:

```bash
python3 -m http.server 3000 --directory _site
```

Then open:

```text
http://localhost:3000
```

## Verify

After deployment:

1. Open the Pages URL or custom domain.
2. Confirm the CSS and JavaScript load.
3. Confirm the GitHub link opens the repository.
4. If `assets/js/config.js` has a `chatEndpoint`, submit a test prompt and confirm the response appears.
5. If `chatEndpoint` is empty, submit should show a clear static-hosting configuration error.
